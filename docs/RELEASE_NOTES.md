## smart-CS2-OB-v1.1.261008 · 2026-10-08 · 内存护栏 + OBS 自带回放缓冲（真机验证）

**一句话**：针对"用着用着整机卡死（正在直播时直播间也卡死）"和"画质不损失能不能把内存从 10 G 降到几十 MB"
这两件事，加了**事前护栏 + 事中哨兵**，并新增第二个回放后端：直接用 **OBS 自带的 Replay Buffer**。

### 🛡️ 新增：内存护栏（默认开）—— 把"能发生"变成"不可能发生"
4K60 十秒 = 一份 19.9 GB、两份 **39.8 GB**，比很多机器的物理内存还大 —— 一旦真去分配，
整机就会进换页风暴，**直播和游戏一起卡死**（这正是"所有软件都不能用"那类症状的典型来源）。
现在启动时按**真实画布/帧率/时长**算出"要占多少"，和物理内存比：

- 超过安全线 → 自动把单段时长压到装得下的值，并**明确告诉你压到几秒**；
- 怎么压都装不下 → **拒绝启用回放**（宁可没有回放，也不能把整台机器拖死）；
- 画布从 OBS 配置里读（`basic.ini` 的 `BaseCX/BaseCY/FPSCommon`），不是猜 1080p。

### 🧠 新增：资源哨兵 + 磁盘护栏
- 引擎每 2 秒看一次可用内存：低于 12% 警告（带数字和"谁在吃"），低于 6% **主动把滚动缓冲还回去**；
- 按保存键前看目标盘剩余空间，不够就先说清楚（避免写半个文件）；
- 顺带修掉一个隐患：键盘钩子回调原来是"一个按键起一个线程"，极端情况下会拖慢系统输入 ——
  现在回调只入队，执行在固定工作线程；另有 `key_mode="poll"`（`GetAsyncKeyState` 轮询）可选。

### 🎛 新增：第二个回放后端 —— OBS 自带 Replay Buffer（内存 GB → MB）
设置窗口 → ① 回放与按键 → 「回放后端」选 **OBS 自带 Replay Buffer**：

| | 插件后端（默认） | **OBS 后端** |
|---|---|---|
| 内存（1080p60 十秒） | 9.95 GB | **≈ 50 MB** |
| 内存（4K60 十秒） | 39.8 GB | **≈ 50 MB** |
| 画质 | 未压缩原始帧 | 多一代 NVENC（码率给足时肉眼无感），**裁切 `-c copy` 零损失** |
| 代价 | 要插件 | 要 OBS 里启用回放缓冲 + 本机 ffmpeg + 回放场景有媒体源（引擎自动建） |

用法完全不变：`←` 标入点、`→` 裁片段、播放键切画面、留档键另存（网页端也能留档：`/control/save`）。
**已在真机（OBS 32.x，1080p60，NVENC，回放缓冲 20 秒）跑通全流程**，逐秒抽帧核对内容无误。

### 🐛 真机验证时揪出来并修掉的问题
- **假警告**：obs 后端把"插件的单段上限 10 秒"当成回放缓冲上限，明明没丢帧也报
  "超过缓冲上限、从 2 秒处开始播" → 改成按 **OBS 自己的回放缓冲时长**判断。
- **回放被砍掉结尾**：`-c copy` 裁切会**往回对齐关键帧**（实测"要 8 秒"得到 10.03 秒），
  原来按"要的秒数"算播放时长 → 回放提前 2 秒切走。现在一律按**文件实际时长**算。
- **播完挂着最后一帧 5 秒**：obs 后端原来只靠"时长 + 5 秒兜底"收尾 → 现在媒体一播完就切回直播。
- **磁盘越攒越多**：OBS 每存一次缓冲就新写一个文件（约 25 MB/次），引擎裁完会删掉原始文件
  和上一次的工作副本，录像目录里始终只剩当前一段。
- **`Replay buffer is not available`**：根因是 OBS 里没勾"启用回放缓冲"（勾完要**重启一次** OBS）；
  引擎现在启动时就检查并直接告诉你这两点，读不到时长时会改读 OBS 配置文件。
- **⚠️ 常驻缓冲模式下回放整个失效**（第二轮真机测试抓到的功能性 bug）：
  obs 后端在「常驻缓冲」模式下**根本没启动 OBS 的回放缓冲**，按出点键时 OBS 直接回
  `SaveReplayBuffer 501`，一整段素材白打。根因是那句"只有省内存模式才开缓冲"的判断
  是给插件后端写的。已修（启动时常驻模式就开缓冲 / 切模式时跟着 arm、release / 关回放时停掉）。
- **明明装了 ffmpeg 却说没有**：`winget` 装完 PATH 往往要新开终端才生效 → 新增 `find_ffmpeg()`：
  配置 → PATH → **程序目录旁边的 `ffmpeg.exe`** → winget / chocolatey / scoop / `C:\ffmpeg\bin`，
  都没有才报错。这也让"发给别人"更简单：把 `ffmpeg.exe` 丢进程序目录即可，不用教对方改 PATH。
- **插件不再是"必须装"**：首次设置向导第 4 步和 `--selftest` 原来**无条件**要求 obs-replay-source，
  现在按**当前用的后端**体检（选 obs 后端时改查 ffmpeg + 回放缓冲，并直说"不需要那个插件"）；
  当前后端不可用而另一条路可用时会**自动切过去**并说明。设置窗口里也会把用不上的字段标灰/标注。

### 📦 开箱即用：所有依赖都打进包里了（2026-10-09）

**之前**：想用省内存的「OBS 自带 Replay Buffer」后端，得自己去下载 ffmpeg、解压、配 PATH ——
这是整个流程里**最容易卡住**的一步（真机上就有用户卡在这儿，回放整段用不了）。

**现在**：`python build_exe.py` 会把 ffmpeg **一起打包进去**：

- 成品文件夹里多一个 `ffmpeg.exe`（和 `开始导播.exe` 同级），引擎自己会找它（`find_ffmpeg()`）；
- zip 从约 12 MB 变成约 49 MB —— 对方解压完**什么都不用装**：不装 Python、不装 ffmpeg、不装插件；
- 随包带上第三方许可证与来源说明（`ffmpeg-说明.txt` + `ffmpeg-LICENSE.txt`，GPLv3）；
- 不想要就 `python build_exe.py --no-ffmpeg`（回到 12 MB，用户需要自己装 ffmpeg）。

### 📖 新增：`新手教程.md`（写给第一次用的人）

从"先看电脑上有没有 OBS/CS2"一路写到"开播后按哪几个键"，每步都有**怎么确认成了**和
**卡住了怎么办**；压缩包里也放了一份（解压就能看到）。README 顶部新增
「🚀 开箱即用」一节，把最精简的四步和两个关键选择（自动切换 / 省内存后端）摆在一屏里。

### 🧪 第二轮真机验证（2026-10-09）- `trim_mode=exact`（重编码到帧）：入点对齐到**完全相同的帧**（原始文件 t=8.0s 与片段首帧都是
  `SEC 42`），要 8 秒得到 8.02 秒；8 秒 1080p60 重编码约 1.1 秒。
- "入点滚出缓冲"路径：等 25 / 40 秒再按出点键 → 正确提示"超过 OBS 回放缓冲的 20 秒"并给整段文件。
- 实测 **OBS 实际留住的比设置值略少**（设 20 秒 → 存出 16.6~19.1 秒），所以文档改成
  "OBS 回放缓冲时长设成**单段上限的 2 倍**"。

### 🔄 修复：设置窗口的开关现在会**立刻同步**到正在运行的引擎（2026-10-09）

用户反馈："电脑 GUI 里勾选了自动切换，但就是不切，好像和手机端不同步。"

根因：设置窗口只写 `config.json`，而**跑着的引擎内存里还是旧值**（要重启引擎才生效）；
手机页面显示的却是引擎的真实状态 —— 于是"窗口里勾了、手机上还是关的"。

现在：窗口里改完保存（以及勾/取消「自动切换」那一下）会**自动调引擎的 `/auto` `/feature`
接口把开关推过去**（就是手机页面用的那两个接口，带口令），日志会写
「✅ 已同步到正在运行的引擎：自动切换 开 · 灵敏度 …」；引擎没在跑时会提示
"改动会在下次启动引擎时生效"。窗口里点「启动引擎」后也会自动同步一次，
保证"窗口上看到的 = 引擎正在做的"。

### 🗣 修复：`⚠️ 有字符没打出来：` 后面什么都没有（2026-10-09）

用户反馈：发送控制台指令时每条都跟一句空警告。根因是把两种完全不同的失败混成了一个 `ok=False`：

- **字符表里没有这个字符**（会列出来，原样跳过）；
- **按键根本没送出去**（`SendInput` 返回 0）—— 这时 `bad` 是空的，于是警告后面什么都没有。

现在分开报：`⚠️ 打不出来的字符（已跳过）：…` / `⚠️ 按键没送出去（SendInput 返回 0）`，
并且**第一次遇到就打印原因和修法**：

> 最常见原因：**CS2 用管理员身份运行，而本程序不是**（Windows 的 UIPI 不允许低权限进程
> 往高权限窗口注入按键）→ 把本程序也「以管理员身份运行」一次，或别用管理员启动 CS2；
> 两边一致还不灵就查安全软件白名单。

顺带：自动切换遇到同样情况时的提示也补上了这段原因（它本来就会在连续失败后自我停用）。
**这两种症状是同一个根因** —— 控制台指令和自动切换都靠 `SendInput` 注入按键。

### 🩹 又一轮真机反馈（2026-10-09）：选了 obs 后端但没装 ffmpeg
- **回放不该整段死掉**：用户机器上插件明明是装着的，只因为"后端停在 obs + 没 ffmpeg"，
  引擎就什么都不干了。现在 obs 后端没准备好时会**自动退回插件后端**并说明原因
  （只改本次运行，不偷偷改 `config.json`）；插件后端找不到回放源时也会提示"其实可以用 obs 后端"。
- **"OBS 回放缓冲时长：(读不到)"** → 内存体检现在也会退回读 OBS 配置文件。
- **不再把"装了插件"误判成"没装"**：插件检测同时查 `GetInputKindList` 和 `GetInputList`。

## smart-CS2-OB-v1.1.261007 · 2026-10-07 · 图形设置界面 + 按键可改 + 回放功能可关

**一句话**：从"改 JSON 的脚本"变成"能双击的设置窗口"，同时把三个老被追问的问题给了答案和开关 ——
内存那 10 G 是哪来的、存出来的视频为什么这么大、键盘不合手怎么办。

### 🖥️ 新增：桌面设置窗口
双击 `开始导播.exe` 就开（`5-设置界面.cmd`、`python replay_director.py --gui` 等价）。
四个大按钮页 —— **① 回放与按键 / ② 副驾 存盘 / ③ CS 控制台指令 / ④ 场景** —— 加下方常驻的「引擎与日志」：

- 开关「回放功能」、选内存模式、改单段秒数/速度，改一下立刻重算内存占用；
- 点「修改」**按一下你要用的键**就完成改键（不需要知道键名），也能一键恢复默认；
- 自动切换、灵敏度三档、对枪胜率加成、显示名字、存盘后处理 —— 手机页面上有的，GUI 里都有；
- 一键启动/停止引擎、运行首次设置向导、做内存体检，日志直接打在窗口下方。

> ⚠️ **双击行为变了**：以前旁边没有 `config.json` 时会直接拉首次设置向导，现在**先开设置窗口**
> （第一次用会问一句要不要现在跑向导）。带参数的命令行行为完全不变，`6-director.cmd` 照旧。

### ⌨️ 新增：按键可以改（适应不同键盘）
四个动作各可绑定一到多个键，默认 `←` / `→` / 小键盘 `6` / 小键盘 `Enter`。
笔记本与 60% 键盘没有小键盘？把「播放 / 收起回放」改成 `F8`、「保留片段」改成 `F9`，
顺便摆脱"NumLock 灯没亮时小键盘 6 和 → 同码"的老问题。

改法三种：设置窗口里按一下 / `--set-keys` 交互 / `--bind play=f8 --save-bind`。
键名写错或两个动作抢同一个键都会明确提示并**只忽略那一条**，不会让四个键一起失灵。

### 🎛 新增：回放功能总开关（默认 **关**）
关着的时候 `←` / `→` / 留档 / 播放 四个键只提示不动手，并且引擎会调用插件的
`ReplaySource.Disable`（+ `Clear`）**把滚动缓冲那几 GB 内存真的还回去**。
手机副驾提示器和自动切观察位**不受影响**，照常工作。

### 🧠 新增：省内存模式（默认）—— 内存里只留最近这一段
- `armed`（默认）：平时插件是 Disable 的（≈0 占用）；按**入点键**才 `Enable` 开始攒帧，
  按**出点键**取走这一段的瞬间立刻 `Disable` 释放滚动缓冲 —— 内存里只剩最近裁出的那一段。
  代价写在文档里：这个模式下入点键不能"往回标"，片段从按下那一刻开始（本来就是推荐打法）。
- `buffer`（旧行为）：一直攒着最近 N 秒，入点可以标在已经过去的某一刻，代价是那份内存一直占着。

### 🩺 内存体检 + 把那 10 G 讲清楚
不是内存泄漏：插件把最近 N 秒的**未压缩**帧放在内存里，`画布×高×4 字节×帧率×秒数`，
同时留两份（正在回填的滚动缓冲 + 已取出的那段）：

| 画布 | 时长 | 一份 | 两份 |
|---|---|---|---|
| 1080p@60 | 10 s | 4.98 GB | **9.95 GB** |
| 4K@60 | 10 s | 19.9 GB | **39.8 GB** |

启动时自动体检：按真实画布/帧率打印数字、数 `replay_source` 实例，并核对会**静默翻倍**的
`Maximum replays`（1~10）与 `Capture internal frames`，默认自动写回安全值。
（旧日志里"1080p 约 1.9 GB"是错的，差 5 倍，已修正 —— 就是它让人以为内存溢出。）

### ⌨️ 新增：开播前自动输入 CS 控制台指令（支持多条）
设置窗口第 ③ 页一行一条填进去，引擎替你"打开控制台 → 逐条输入并回车 → 关掉"。
三种时机：引擎启动后等 CS2 到前台发一次（默认）/ 每场第 1 个冻结时间 / 只手动（窗口按钮或 `GET /control/console`）。
安全阀：**只有 CS2 在前台才发键**，否则一个字都不发；空跑模式（`--dry-run`）只打日志不真发键。

### 📦 新增：留档文件的体积体检与可选压小
每次按保存键后报「体积 + 实测 Mbps」，并区分两条编码通路：

| | 容器 | 编码 | 4K60 十秒 |
|---|---|---|---|
| 默认（非无损） | `.flv` | H.264 **CRF 23 / veryfast** + AAC | 20 ~ 60 MB |
| 插件「Lossless」开着 | `.avi` | **utvideo 无损** + pcm | **1 ~ 2.5 GB** |

- 看到 `.avi` 就说明踩了无损，引擎会当场**自动关掉** `lossless` 并警告；
- `save_postprocess` 可选 `remux`（`.flv → .mp4`，`-c copy`，零损失、秒级）
  或 `reencode`（libx264 CRF26 压小，需要 ffmpeg）。没装 ffmpeg / 处理失败 → 只跳过，**原文件绝不动**。

### 🧪 新增：自检与打包双闸门
- `开始导播.exe --selftest`：逐条验 `websocket-client`、`tkinter`、键位表、内存公式，并列出还需要的外部条件。
- `build_exe.py` 打包前检查依赖、打包后**拿真的 exe 跑一次自检**，不过就拒绝出包。
  （这来自一个真实的坑：打包机没装 `websocket-client` 时 `--hidden-import` 只警告不报错，
  产物双击能开、一连 OBS 就崩，见 `docs/技术笔记.md` §10.6。）

### 🐛 修掉的问题
- `config.json` 带 BOM（记事本另存 UTF-8）会让引擎**启动失败** → 改用 `utf-8-sig` 读。
- 启动时无条件 `ReplaySource.Replay` 冲缓冲会**立刻分配第二份**内存 → 只在常驻缓冲模式才冲。
- `round1` 模式下冻结时间 10Hz 的 GSI 包会让控制台指令**重复发送十几次** → 改为"先占位再起线程"。
- 设置窗口选项变多后，最后一块被挤出可视区导致"找不到" → 改成一排大按钮分页，尺寸自适应屏幕。
- 空跑模式（`--dry-run`）下也能用 HTTP 端点驱动完整流程（此前没有键盘控制器，端点全部无效）。
