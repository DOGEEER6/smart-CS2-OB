# smart-CS2-OB · CS2 智能导播副驾

**给单人导播的 CS2 赛事辅助工具：一键回放 + 手机副驾提示器 + 自动切观察位。**

打 CS2 比赛时，导播要同时干三件事：盯着谁在打、把观察位切过去、抓一段刚打完的回放。
一个人干这些基本等于手忙脚乱 —— 镜头切晚了、回放抓早了、精彩镜头全漏了。

这个工具把这三件事各自压缩成一个动作：

| 你原本要做的事 | 现在要做的事 |
|---|---|
| 判断"现在谁在打、镜头该给谁" | **瞄一眼手机**，上面写着大字「按 [ 7 ]」 |
| 交火瞬间腾不出手按键 | **打之前按一下 `←`、打完了按一下 `→`**，这一段就裁好了 |
| 手动切场景、放回放、掐时间切回来 | **按一下小键盘 `Enter`**，播完自动切回直播 |
| 精彩片段想留档发出去 | **按一下小键盘 `6`**，这段素材直接存成视频文件 |

> 上面四个键都是**默认值**：想换成 `F8` / `F9` 之类（比如 60% 键盘没有小键盘），
> 双击 `开始导播.exe` 在设置窗口里点一下「修改」就行 —— 见 [快捷键](#快捷键)。
| 全程手动切 POV | 打开**自动切换**，它替你按数字键 |

## 它解决什么问题

**1. "现在该把镜头给谁"是个实时判断，但导播的手是满的。**
所以判断放在手机上 —— 一张永远只显示"按几号键"的网页，不用装 App，不会打断游戏操作。

**2. 回放和直播抢时间。**
即时回放要么提前开录（占硬盘、还可能错过开头），要么等打完了再想抓（已经晚了）。
这里用 [Exeldro 的 obs-replay-source](https://github.com/exeldro/obs-replay-source) 在内存里滚动缓冲最近 N 秒，
所以**回合结束再按也来得及** —— 精彩的那一秒已经在缓冲里了。
（默认的**省内存模式**下，缓冲是"按入点键那一刻才开始攒"，所以现在推荐的打法是"打之前按 `←`"，
详见 [内存模式](#内存模式replay_mode默认-armed省内存)。）

**3. 回放切回来那一下会"卡"。**
常见做法是定时器估算播放时长再切场景，长度算错就会掐掉画面或者黑屏。
这里让**插件自己在播完那一帧切回直播场景**（`next_scene` 属性），引擎只负责收尾。
实测：14.2 秒素材播放全程 17/17 帧画面都在动，没有一帧是静止的。

## 核心特性

- 🎬 **两键框选回放** —— `←` 标入点、`→` 标出点，"入点 → 出点"当场成片，`Enter`（默认小键盘）播放
- 🖥️ **桌面设置窗口** —— 双击 `开始导播.exe`（或 `5-设置界面.cmd`）打开：开关回放、选内存模式、**现场改按键**、看内存估算、启动/停止引擎、看日志
- ⌨️ **按键可以改** —— 四个动作各能绑一个或多个键；没有小键盘的 60% / TKL 键盘把「播放」改成 `F8`、「留档」改成 `F9` 就行
- 🎛 **回放功能总开关（默认关闭）** —— 关着的时候四个回放键只提示、不动手，插件内存直接还回去；**提示器和自动切观察位照常工作**
- 🧠 **省内存模式（默认）** —— 平时插件不占内存，按**入点键**那一刻才开始攒帧，裁完立刻释放，内存里只剩最近这一段
- 🩺 **内存体检** —— 启动时按真实画布/帧率/时长把占用算出来，并揪出会让内存悄悄翻倍的插件设置；`9-memory-check.cmd` 可单独跑
- ✂️ **入点由你说了算** —— 不再是"最近 N 秒"或自动识别击杀：裁哪一段完全取决于你按 `←` 的时机（引擎用 `StartDelay` 负值真跳片头，不是快进）
- 🎁 **包装转场不吃片头、也不多卡那零点几秒** —— 切场景后先把回放定格在第一帧，等包装**动画**放完再开播（本机素材 3.35 秒，但动画 2.95 秒就完了 → 只等 2.95 秒）
- 💾 **小键盘 `6` 留档** —— 把当前这段素材存成 `.flv`（存到 OBS 录制目录，内容和回放一致）
- 📱 **手机副驾提示器** —— SSE 实时推送，浏览器打开就用，不用装 App，口令保护
- 🤖 **自动切观察位** —— 三档灵敏度随时在手机上切，真打起来会绕过门槛直接切
- ⚔️ **对枪胜率预测** —— 按血量/护甲/武器/本场 KD 算这一枪谁能赢，镜头偏向活下来的一方
- 🧱 **交火分层** —— 层级优先于分数，避免"架枪的抢走正在对枪的视角"
- 🛡️ **安全阀** —— 只有 CS2 在前台才发按键；连续切不动会自我停用并打印排查提示
- 🧙 **首次设置向导** —— 自动找 CS2、读 OBS 密码、检查插件、认场景、放行防火墙，8 步零手抄
- 📦 **可以打包成 exe** —— `build_exe.py --clean` 出一个自带 Python 的文件夹版，拷到别人电脑直接跑

## 快速开始

### 方式一：用打好的成品（推荐，不需要装 Python）

> 拿到的是 **`CS2导播助手.zip`**（约 12 MB）就先解压，然后双击里面的 `开始导播.exe`；
> 拿到的是整个 `CS2导播助手\` 文件夹就直接双击（别只拷 exe，`_internal\` 必须一起）。

```bat
:: 1. 打开 OBS（不用开播）
:: 2. 第一次用：双击
先运行我-首次设置.cmd
:: 3. UAC 弹窗点「是」
::    看到 "🎉 全部就绪！" 就成了
:: 4. 以后每次开播：双击
开始导播.exe
::    → 弹出的是【设置窗口】，不是黑窗口
::    → 在窗口里按需改键 / 打开「回放功能」
::    → 点窗口里的「启动引擎」才开始导播
```

> ⚠️ **双击行为从 2026-10-07 起变了**：以前旁边没有 `config.json` 时双击 exe 会直接拉首次设置向导，
> 现在双击**先开设置窗口**（窗口里有「首次设置向导」按钮）。
> 带参数的命令行行为**完全不变** —— `6-director.cmd` 照旧直接跑引擎。
> 想强制走命令行：`开始导播.exe --no-gui`（或者用 `6-director.cmd`）。

设置窗口关掉不影响导播；导播是窗口里点「启动引擎」拉起来的那个进程，
日志会直接打在窗口下方的日志区（也可以点「内存体检」「首次设置向导」）。

引擎起来后，黑窗口/日志里会打印一行手机地址，形如：

```
http://192.168.66.221:23417/?k=你的口令     ← 一般是这个
```

手机连同一个 WiFi，打开这个地址（**`?k=` 一起带上**），加进主屏幕书签即可。

### 方式二：从源码跑

```bat
git clone https://github.com/DOGEEER6/smart-CS2-OB.git
cd smart-CS2-OB
pip install websocket-client
python setup_wizard.py       :: 首次设置（--check 只自检、--dry-run 演练）
python replay_director.py    :: 双击 exe 一样的效果：打开设置窗口，点「启动引擎」开跑
python replay_director.py --no-gui   :: 不开窗口，直接命令行跑引擎
```

> 图形界面需要 Python 自带 `tkinter`（官方安装包默认就有）。没有也能跑，只是没窗口：
> 用 `6-director.cmd` 或 `--no-gui`。

### 方式三：自己打成 exe

```bat
pip install pyinstaller websocket-client
python build_exe.py --clean
:: 产物：CS2导播助手\   （整个文件夹一起拷走才能用）
```

> 默认打**文件夹版**（onedir）。单文件版（`--mode onefile`）每次启动都要解压到 `%TEMP%`，
> 一旦被组策略 / 杀软 / 沙箱拦就整个起不来，只报一句 `Could not create temporary directory!`，
> 排查代价极高。**建议就用文件夹版。**

### 首次设置向导做了什么

| 步骤 | 干什么 | 安全设计 |
|---|---|---|
| 1 | 找 CS2 安装目录 | 读 Steam 注册表，自动定位游戏库 |
| 2 | 装 GSI 配置 | 只写 `game\csgo\cfg\`，**不碰老版 CS:GO 残留的 `csgo\cfg\`** |
| 3 | 读 obs-websocket 端口和密码 | 直接读 OBS 自己的配置文件，**不用手抄密码** |
| 4 | 检查 Replay Source 插件 | 没装就明确告诉你去装哪个 |
| 5 | 认场景 | 自动认出直播场景；回放场景 / 回放源缺了就建一个 |
| 6 | 写插件参数 | **只写空着的或明显不对的**，你已经调好的值一律保留 |
| 7 | 放行手机访问 | 加一条防火墙入站规则，`remoteip=LocalSubnet` 只放行局域网 |
| 8 | 端到端自检 | 逐项告诉你哪里还没通 |

**对已经配好的系统零改动**，重复跑是安全的。

## 快捷键

全局钩子是**只读**的（`WH_KEYBOARD_LL`，不拦截、不注入、不吞键），CS2 和 OBS 该怎么用还怎么用。

**四个回放键的默认值和可改方式**（2026-10-07 起按键可以在设置窗口里改，适应不同键盘）：

| 默认键 | 动作 | 配置字段 |
|---|---|---|
| **`←`** 左方向键 | **标记入点** —— 记住这一刻（精彩镜头开始的地方） | `keys.mark_in` |
| **`→`** 右方向键 | **标记出点 / 裁片段** —— 当场把"入点 → 现在"从滚动缓冲里裁成一段片子 | `keys.mark_out` |
| **小键盘 `6`** | **保留片段** —— 把当前这段素材另存成文件（存到 OBS 的录制目录，赛后能剪出去发） | `keys.save` |
| **小键盘 `Enter`** | **播放 / 收起回放** —— 按一下切到回放场景播放，再按一下立刻切回直播 | `keys.play` |
| **`1` ~ `0`** | 切换观察位（和 CS2 观察位的 1~0 一一对应，**不可改**） | —— |

三种改法：

1. **设置窗口里点「修改」，然后按一下那个键**（推荐，不用查键名）；
2. `--set-keys` 命令行交互，四个动作各按一下；
3. 直接写：`--bind play=f8 --bind save=f9,numpad6 --save-bind`（`--save-bind` 才会写回 `config.json`）。
   看当前键位：`--show-keys`。

每个动作可以绑**多个键**（`config.json` 里是键名列表），默认是：

```jsonc
"keys": {"mark_in": ["left"], "mark_out": ["right"],
         "save": ["numpad6"], "play": ["numpad_enter"]}
```

常用键名：`left / right / up / down / space / tab / enter / numpad_enter / numpad0..9 /
f1..f24 / a..z / 0..9 / backslash / comma / period / slash / semicolon / quote / backtick / minus / equal …`

- **冲突**（两个动作绑同一个键）会被拒绝并提示，**后者忽略**（一个键只能干一件事）。
- **键名写错**只忽略那一个并提示，**不会让四个键一起失灵**（认不出的动作会退回默认键）。

> ⌨️ **没有小键盘的键盘（60% / TKL）**：把「播放 / 收起回放」改成 **`F8`**、「保留片段」改成 **`F9`** 就行
> —— 这就是本次"适应不同键盘"的重点。在设置窗口里各点一次「修改」、各按一下对应的键即可。

> 流程就三步：**打之前按 `←` → 打完了按 `→` → 想放的时候按 `Enter`（默认小键盘）**。
> 引擎**不做任何自动定格**：不按 `→`，手里就没有新素材。
>
> 小键盘 `Enter` 和主键盘 `Enter` 的 `vkCode` 都是 `0x0D`，靠**扩展位**区分，主键盘 Enter 不会误触发。
>
> ⚠️ **NumLock 提醒只在真的绑了小键盘键时才出现**：NumLock 关掉时小键盘 6 发出的就是
> "右方向键 + 扩展位"、scancode 也是同一个 `0x4D` —— 在钩子层面和 `→` 完全同码，区分不开，
> 只能当"标记出点"处理。引擎启动时会检查，**只有当前键位里含 `numpad6` / `numpad_enter` 才提醒**；
> 改成 `F8` / `F9` 之后就不再啰嗦了。

### 回放功能总开关：默认是**关**的

`config.json` 里的 `replay_enabled`，**默认 `false`**。为什么默认关：关着的时候那份几 GB 的滚动缓冲
**根本不占内存**（引擎启动时给插件发 `ReplaySource.Disable` 把滚动缓冲摘掉，再按
`clear_replay_on_disable` 发 `ReplaySource.Clear`，把已经取出来的那一段也清掉）。

| 状态 | 行为 |
|---|---|
| **关**（默认） | `←` / `→` / 保留片段 / 播放 四个键只打一行"回放功能当前是关的"提示，**不动手** |
| **关** | 📱 手机副驾提示器 + 🤖 自动切观察位**不受影响**，照常工作 |
| **开** | 四个键恢复正常；再按 `replay_mode` 决定什么时候占内存 |

三种打开方式：**设置窗口里的勾选框**、**手机页面顶部新的大开关**、或命令行
`--replay on`（配 `--save-bind` 写回配置）。

### 内存模式：`replay_mode`（默认 `armed`，省内存）

| 模式 | 什么时候占内存 | 代价 |
|---|---|---|
| **`armed`**（默认，省内存） | 平时插件是 Disable 的（≈0 占用）；按**入点键**那一刻才 `ReplaySource.Enable` 开始攒帧，按**出点键**把这一段取走的瞬间立刻 `Disable` 释放滚动缓冲 —— **内存里只剩最近这一段** | ⚠️ 入点键不再能"往回标"：片段就是从你按它的那一刻开始（这也正是原来推荐的打法："打之前按 ←"） |
| **`buffer`**（旧行为，常驻缓冲） | 插件一直攒着最近 `record_max_seconds` 秒 | 那份内存**一直占着**；好处是入点键可以标在已经过去的某一刻 |

手机页面顶部现在也有「**省内存** / **常驻缓冲**」两个按钮，随时切（带口令）。

> 相关字段：`free_buffer_after_clip`（默认 true，裁完片段是否立刻释放滚动缓冲）、
> `clear_replay_on_disable`（默认 true，关回放/切模式时是否连"已取出那段"也清掉）。

### `←` / `→`：手动框选片段

`←` 只是记下**时刻**，`→` 才是真正动刀的那一刻：它把"入点 → 现在"这一段从插件的滚动缓冲里裁出来
（靠 `StartDelay` 负值 = `trim_front`，真跳不是快进），然后你按播放键播的就是这一段。

```
[21:28:43] ⏺  【← 标记入点】21:28:43 —— 打完了按【→ 标记出点】把这一段裁出来
[21:28:44]    ✂️ 从入点开始播（跳过素材开头 9.4 秒）
[21:28:44] ⏹  【→ 标记出点】片段已裁好：入点到现在 0.6 秒
[21:28:44]    → 按【Enter】切画面播放；想留档再按【numpad6】存成文件
```

- **出点必须在入点之后 `record_max_seconds`（默认 10）秒内按下** —— 滚动缓冲只留最近这么多秒，
  边打边滚。超了引擎不会硬裁，而是打一行
  `⚠️ 入点已经滚出缓冲了（缓冲里只有 x.x 秒）→ 这一段从头播`，然后照样让你播整段缓冲。
- 📱 **这个窗口在手机上是可见的**：按了 `←` 之后页面顶部出现倒计时横幅
  （`⏺ 入点 3.2 秒 / 还剩 6.8 秒内按 →`），剩 2.5 秒以内变黄 + 震动，滚出缓冲变红 + 再震一下。
  **不用盯着电脑日志数秒** —— 人在打游戏时不会去看日志（这就是 2026-10-06 那次
  "存下来的片段莫名其妙"的根因：`←` 和 `→` 隔了 12.4 秒 > 10 秒缓冲）。
- 每次裁片段都会把缓冲**掏空**、从头重新累积，所以连着裁两次，第二次一定很短。
- 手抖（`←` `→` 挨得太近，默认 < `min_clip_seconds` = 0.3 秒）会被拦下并提示，入点还留着，再按一次 `→` 就行。
- 没按过 `←` 就按 `→`：只提示 `⚠️ 还没标入点：先按【←】标入点…`，**不会去抓**。
- 正在回放中按 `←` / `→` 会被拒绝（先按播放键把回放收掉）。

### 保留片段（默认 `numpad6`）

按一下，插件就把"当前这段素材"写成一个视频文件（`.flv`，H.264），存到 OBS 的录制目录：

```
[18:34:09] 💾 【numpad6 保留片段】已让 OBS 把这段素材写成文件
[18:34:09]    ✔ 已开始写盘：E:/Paris2024/回放_2026-10-06_18.34.09.flv
```

- 存出来的内容和回放里看到的**完全一致**（插件保存时同样会应用裁剪，片头也是从你按 `←` 的入点开始）。
- 文件名格式、存放目录可在 `config.json` 里改：`save_dir`（留空 = 用 OBS 录制目录）、`save_file_format`。
- 写盘是**实时**的，一段 10 秒素材大约要写 10 秒左右，期间别关 OBS。
- 缓冲里一帧都没有时（OBS 刚启动、刚清过缓冲）按下去什么都不会发生 —— 插件自己会拦，不会崩、不会留半个文件。

#### 文件有多大？编码是什么？

插件只有两条通路（`replay-source.c:777-806`，逐行核对过）：

| | 容器 | 编码 | 4K60 十秒大概是 |
|---|---|---|---|
| **默认（非无损）** | `.flv` | H.264 **CRF 23 / veryfast** + AAC | **20 ~ 60 MB** |
| 插件里「Lossless」开着 | `.avi` | **utvideo 无损** + pcm | **1 ~ 2.5 GB**（几十倍） |

- 所以"文件特别大"几乎只有一个原因：**插件的 Lossless 被打开了**。
  引擎每次启动会自动把它关掉，保存完看到 `.avi` 还会再纠一次并打警告 —— 你不用记这件事。
- `.flv` 那条是 **CRF（恒定质量）**，不是恒定码率：画布越大、画面越花就越大，
  典型十几到几十 Mbps，和手机 4K60（≈50 Mbps）**同一个量级**。
- 每次保存后引擎会报体积和实测码率（`📦 文件体积 / 📊 码率约`），超了就告诉你怎么压。
- 想更小：`record_max_seconds` 调小（片段短了自然小）、画布降 1080p，
  或者把 `config.json` 的 **`save_postprocess`** 打开（设置窗口里也有这个下拉框）：
  - `remux` = 只换容器 `.flv → .mp4`（`-c copy`，**零质量损失、秒级**，Windows 上更好播）；
  - `reencode` = 用 libx264 CRF 26 重编码压小（慢几十秒，需要装了 ffmpeg）。

## 每次开播前自动输入 CS 控制台指令

打比赛前你总要往 CS2 控制台敲那几句（`sv_cheats`、`mp_freezetime`、`cl_draw_only_deathnotices`…）。
现在把这些指令填进设置窗口，引擎开播时替你敲：**打开控制台 → 逐条输入并回车 → 关掉控制台**，一条不落。

<p align="center"><img src="docs/gui-3-console.png" width="72%" alt="CS 控制台指令设置页" /></p>
<p align="center"><i>在「③ CS 控制台指令」页里一行一条填进去就行。</i></p>

- 位置：设置窗口里的 **「CS 控制台指令（每次开播前自动输入，一行一条，可多条）」** 文本框。
  它在设置窗口的 **「CS 控制台指令」标签页**里（窗口分了 4 页：回放与按键 / 副驾 存盘 /
  CS 控制台指令 / 场景，底部「引擎与日志」常驻）。
  一行一条；空行和 `//` 开头的行会被忽略；同一行里用 `;` 隔开的多条**原样保留**。
- **触发时机**（三选一）：
  | 选项 | 行为 |
  |---|---|
  | **引擎启动后，等 CS2 到前台就发一次**（默认） | 引擎起来后它在后台等，你切回游戏的那一刻自动敲 |
  | 每场第 1 个冻结时间发一次 | 适合"每张图都要重设一遍"的指令 |
  | 只手动 | 想发的时候点设置窗口的「现在发送一次」（或 `GET /control/console`） |
- **安全阀**：默认**只有 CS2 在前台时才发键**（`cs_console_require_focus`）。
  你切到 OBS / 浏览器时它一个字都不会发，绝不会把命令打进聊天框。
- **控制台键**默认 `` ` ``；如果你的 CS2 把控制台绑在 F10 之类，就改成 `f10`
  （也接受 `backtick` / `numpad_enter` 这类键名）。
- 相关配置：`cs_console_commands`、`cs_console_trigger`、`cs_console_key`、
  `cs_console_delay_ms`（打开控制台后等多久，默认 400）、`cs_console_gap_ms`（两条之间，默认 120）、
  `cs_console_close`（发完是否关掉控制台，默认开）、`cs_console_require_focus`、`cs_console_timeout_s`。

> 实现方式和"自动切观察位"完全一样：**合成按键**（`SendInput` + 扫描码），不是注入游戏、不读内存。
> 所以它要求 CS2 在前台 —— 这既是安全阀，也是它能工作的前提。
> 如果你更希望完全不用按键注入，就把这些指令写进 CS2 的
> `<CS2>\game\csgo\cfg\autoexec.cfg`，游戏启动时会自己执行。

## 内存：那几 GB 到底是哪来的（不是内存泄漏）

> 这是 2026-10-07 用户问得最多的一件事："为什么每次用这个插件都占 10 G？"
> 结论：**不是内存泄漏**，是 obs-replay-source 的设计 —— 它把最近 N 秒的**未压缩**帧放在内存里。

算法就一个乘法：

```
画布宽 × 高 × 4 字节(BGRA) × 帧率 × 秒数
```

实测/计算（`estimate_replay_memory()` 就是照这个算的）：

| 画布 | 时长 | 每帧 | 每秒 | **一份** | 插件同时留**两份** ≈ |
|---|---|---|---|---|---|
| 1080p @ 60 | 10 秒 | 7.9 MB | 475 MB | **4.98 GB** | **9.95 GB**（滚动缓冲 + 已经取出的那一段） |
| 4K @ 60 | 10 秒 | 31.6 MB | 1898 MB | 19.9 GB | **39.8 GB** |

> 4K 那个 39.8 GB 和历史上"任务管理器里 obs64 私有内存 40.86 GB"完全对得上 —— 一直是这个原因。
> ⚠️ 顺便记一笔：**旧版本日志里写的"1080p 约 1.9 GB"是错的**（差了 5 倍），已修正。
>
> 默认的**省内存模式**不会长期占着两份：按入点键时开始攒一份，取走片段的那一瞬间两份同时在，
> 裁完立刻把滚动那份还回去 —— 所以峰值就是上面「两份」那一列，空闲时 ≈0。

**三个会"悄悄让内存翻倍"的设置**（插件里，不是本工具的）：

| 设置 | 后果 |
|---|---|
| 插件的 `Maximum replays`（1~10） | 每多留一段就多**一整份** |
| 插件的 `Capture internal frames` | 开着通常**再多一份** |
| 场景里存在**多个** `replay_source` 实例 | 每个实例**自己攒一份** |

**现在引擎启动会做内存体检**（`_memory_audit()`）：按真实画布/帧率/时长打印数字，数 `replay_source`
实例个数，并用上面的公式核对这三项。`memory_autofix`（默认 true）会把 `replays` 写回 **1**、
把 `internal frames` **关掉**。

想更省内存：`record_max_seconds` 从 10 秒调小（**减半省一半**）、画布/帧率降一档、或者干脆
**关掉回放功能**（0 占用）。

单独体检命令：`--memory-report`，或双击 **`9-memory-check.cmd`**（要先开着 OBS 才能读到真实画布）。

> 想追到插件源码一级的依据（`replay.h` / `replay-source.c` 里滚动缓冲怎么攒、`Disable`/`Clear`
> 到底释放了什么）见 **[docs/技术笔记.md](docs/技术笔记.md)** —— README 只讲"有什么、怎么用"。

## 镜头是怎么决定切给谁的

### 第一步：每个 GSI 包给 10 个人打分

GSI 的 `allplayers` 里有**位置**和**朝向**（`forward`），所以能算出"他在瞄谁"：
朝向夹角用 `atan2(forward[0], forward[1])` 求。

| 信号 | 分值 | 含义 |
|---|---|---|
| `taking_damage` | **70** | 这一包血量掉了 —— 最强的信号，他正在挨打 |
| `mutual_aim` | **60** | 他和他面前的敌人互相在瞄 —— 对枪一触即发 |
| `aiming_enemy` | 25 | 他在瞄一个敌人（单向，例如架枪） |
| `enemy_very_close` | 25 | 最近敌人 < 500 单位 |
| `just_killed` | 30 | 3 秒内刚拿到击杀 |
| `last_alive` | 25 | 自己队只剩他一个（残局） |
| `nade_incoming` | 18 | 附近有飞行中的道具 |
| `flashed` | 15 | 被闪了 |
| `has_bomb` | 14 | 拿着 C4 |
| `enemy_close` | 12 | 最近敌人 < 1000 单位 |
| `near_bomb_ct` | 12 | 已下包，他离包很近（拆包位） |
| `low_hp` | 10 | 残血 |
| `sniper` | 8 | 拿狙击 |
| `observed` | 6 | 当前正在看的这个（轻微粘性，防抖） |
| `STICKY_BONUS` | 14 | 上一包的第一名给点加成，防止列表闪烁 |

### 第二步：交火主导权 + **分层**（最关键的修正）

只按分数相加会出大问题：

```
架枪的人       = aiming_enemy 25 + enemy_very_close 25         = 50
包匪+残局+包点 = has_bomb 14 + last_alive 25 + near_bomb_ct 12 = 51
真在打的人     = mutual_aim 60                                 = 60
```

实测复现过：`只按分数排 → 对枪 A 172 / 架枪 D 173`，差 1 分就切错了。
结果就是——**有人正打着，镜头却切到后面拿包的残局哥身上**。

修法是两层：

**① 交火主导权**：只要他正在参与一场即将发生的交火，额外加一大笔分。

```
强交火（互相瞄 / 正在掉血） → +130，并且锁定镜头不许切走
弱交火（单向瞄且敌人很近）  → +70，压得过静态叙事，但不锁镜头
```

**② 层级优先于分数**：排序键是 `(tier, -score)`，不是单纯比分数。

| 层级 | 条件 |
|---|---|
| **tier 0** 真在打 | 正在掉血，或（互相瞄 且 距离 < 1200） |
| **tier 1** 对峙 | 在瞄人 且 距离 < 1600 |
| **tier 2** 其余 | 按叙事价值排（残局、拿包、连杀…） |

于是"架枪的"哪怕叠满静态信号（实测能叠到 243 分），也**永远排在 tier 0 的真交火后面**。
自动切换端也配合：层级跃升时**绕过**分数门槛和领先差值，因为真打起来了必须切。

> ⚠️ GSI **不提供视线遮挡信息**，"在瞄人"只有角度判定 —— 隔墙把准星对着附近敌人也会触发。
> 所以有强弱之分：隔墙瞄人只拿 70 分、不锁镜头，不会把画面焊死。

### 第三步：对枪胜率

镜头应该偏向"能活下来的一方"，所以带一个启发式的胜率模型（**可解释，不是黑盒**）：

```
power = hp × 0.78 + 护甲×6 + 头盔×4 + 武器威力(距离) × 0.52
       − 被闪 22 − 着火了 8 ± 本场 K/D 项 ± 本轮伤害项
prob  = 1 / (1 + exp(−(powerA − powerB) / 22))

加成 = 42 × (prob − 0.5) × 2 × mul     mul = 1.0 互相瞄 / 0.5 单向先手
```

单元测试覆盖：满血 AK vs 残血 AK → 92%；对等 → 50%；AWP 远 63% / 近 36%；
手枪 vs 步枪 26%；被闪 27%；霰弹贴脸 52%；本场 KD 2.5 vs 0.4 → 63%。

> 武器威力按 **(远距离, 近距离)** 两档建表。**只认 `state == "active"` 的那把**——
> GSI 的 `weapons` 字典会残留以前捡过的枪（实测：手里是 `glock`，栏位里躺着 `awp`），
> 按整个武器栏判定会把拿手枪的人算成 AWP 选手，还会连带毁掉胜率预测。

### 第四步：安全阀

- **只有 CS2 在前台才发按键**（`auto_require_focus`，前台进程名必须是 `cs2.exe`）。
  否则合成的数字键会打进 OBS，乱切场景。
- **切完 1.2 秒内回查 GSI 的 `observer_slot`**，看镜头是不是真切过去了。
  **连续失败 3 次就自动关闭自己**，并打印排查步骤（游戏没焦点 / 键位没绑 / 安全软件拦截）。
- 正在回放、镜头被锁（tier 0 近距离互相瞄）时不切。
- 按键用 `SendInput` + **扫描码**（`KEYEVENTF_SCANCODE`）注入，不是 `keybd_event`。
  （验证方式：自己装一个键盘钩子去抓注入的 `7` —— 钩子能抓到，说明通路可用。）

## 一键回放是怎么做到不丢镜头的

```
你按了 →（标出点）
        │
        ├─ 插件在内存里滚动缓冲，素材已经在手上了
        ├─ 读 OBS 日志拿到素材真实长度（按字节偏移读新增内容）
        ├─ 算播放时长： hold = 素材秒数 ÷ speed(0.7)
        │
        ├─ 切到回放场景 → 显示回放源 → 触发 ReplaySource.Replay 热键
        │      （插件里这个热键 = Load replay：从滚动缓冲取一段素材）
        │      （参数里写好 next_scene = 直播场景，交给插件自己切回来）
        │
        └─ 收尾：先把场景切回直播，再隐藏回放源
                 （反过来会闪一帧黑屏）
```

踩过的四个坑，都修在代码里了：

1. **裁片段和播放抢线程** —— 读 OBS 日志要 0.5~1 s，期间用户按了播放键就会读到**上一次的旧素材长度**。
   → 加 `threading.RLock()` 把"选素材 + 读长度 + 算时长"整段锁住。
2. **按文本差异判断 OBS 日志新行是错的** —— `replay added of 12.00 seconds` 每次文本一模一样。
   → 改成按**字节偏移**读新写入的部分。
3. **长度未知时往短了猜** —— 用默认 5 秒估时长，12 秒的素材只播 7 秒。
   → 改成按上限给足，**绝不往短了猜**。
4. **在 obs-websocket 接收线程里发请求 → 死锁** ——
   `on_obs_event` 回调在接收线程里执行，回调里又发 `SetSceneItemEnabled`
   → 响应要由同一个被阻塞的线程来收 → `TimeoutError`。
   → 事件丢进 `queue.Queue()`，由独立的 `_event_loop()` 线程消费。

### 回放长度：入点由你按 `←` 的那一刻决定

**2026-10-06 用户决定：去掉所有自动定格，改成手动框选**（"去掉自动固定，用左右键截取片段，
左标记入点，右标记出点，小键盘回车播放"）。原来是"回合结束自动定格 + 固定只播最后 N 秒"，
再往前还有两版"识别决胜击杀 / 多杀连杀按串头对齐"——那些参数多、现场不好预期，现在整套删掉。

现在的流程：

```
打之前按 ←  →  （记住入点时刻）  →  打完了按 →  →  当场裁出「入点 → 现在」
                                              ↓
                                        按小键盘 Enter 播放
```

`→` 按下时算的就是这一件事：

```
elapsed = now - 入点时刻
avail   = min(record_max_seconds, now - 上次裁片时刻)   # 缓冲只留最近这么多秒
skip    = max(0, avail - elapsed)                       # 要跳过的片头长度
```

- **超时兜底**：`elapsed > avail + 0.2` 说明入点已经被滚动缓冲滚掉了，这时不硬裁，
  打一行 `⚠️ 入点已经滚出缓冲了（缓冲里只有 x.x 秒）→ 这一段从头播`，把整段缓冲给你播。
- **掏空效应**：每次裁片段（插件 `Load replay`）都会清空滤镜缓冲并重新累积，
  所以紧接着再裁一次，第二次一定很短 —— 这也是"出点必须当场按"的原因。
- **手抖保护**：`←` 到 `→` 少于 `min_clip_seconds`（默认 0.3 秒）会被拦下并提示，入点保留。
- **没按 `←` 就按 `→`**：只提示先按 `←`，不抓。
- **手里没有裁好的片段时按小键盘 Enter**：只提示 `⚠️ 还没有裁好的片段 —— 先按【←】…`，
  **不会**再偷偷替你去定格（旧版会自动定格一次，已删）。

`skip` 写进 Replay Source 的 `start_delay`（**负值**）。插件源码
（`replay-source.c`）里 `replay_retrieve` 对负 `start_delay` 写
`new_replay.trim_front = start_delay * -1`，播放时 `replay_restart_at_begin`
直接 seek 到 `first_frame_timestamp + trim_front` —— 是**真跳**，不是快进；
而且 `|trim_front|` 超过片段总长时插件那个分支不成立，会**原样从头播**，
所以算过头也不会把片子裁没。改这个设置也不会重建滤镜、不会冲掉滚动缓冲。

第一次写入时引擎会自检一次（写值→读回→比对）并打日志；插件不认这个键就退回
"从片头整段播"，日志里会写 `⚠️ 入点通路自检失败：想写 StartDelay=-4000，读回 0`。

### 包装转场为什么不再吃掉片头（2026-10-06 修）

用户反馈："转场会覆盖掉前面一部分"。查下来是真的：

- OBS 当前转场是 `obs_stinger_transition`（名字叫「转场」），素材
  `J:/比赛包装/01_Logo_transition_long.mov`，**总长 3.35 秒**。
- stinger 是"全屏盖住"的包装：切场景那一刻起它就压在节目画面上，1.0 秒才真正切过去、
  3.35 秒才放完。而回放源在切场景的**同一瞬间**就开始播了 → 前 3.35 秒观众根本看不到。
- ⚠️ 但**文件时长 ≠ 动画时长**（2026-10-06 晚修）：实测这个 3.35 秒的素材，**最后 0.40 秒
  是全透明黑帧**（8×8 采样下 alpha=6/255、luma=0）—— 动画 2.95 秒就放完了，之后观众看到的
  是"盖在透明包装下面的定格回放画面"，一动不动。原来要等满 3.35 秒，于是按完小键盘 Enter
  会先卡 0.4 秒（用户原话："播放前会卡零点几秒不动"）。现在 `stinger_visible_seconds()`
  用 ffmpeg 把 alpha 抽成 8×8 灰度序列（201 帧才 12 KB），从尾巴往前跳过全透明帧，量出
  动画真正结束在 **2.95 秒** 就开播 —— 只提前、不推后，下限是 `transition_point`。
- API **问不出**它的时长（`transitionFixed=true` 时 `transitionDuration` 是 `null`），
  所以这里直接读那个 `.mov` 的文件头（`moov`/`mvhd` box，纯标准库，不装任何依赖）。

现在的做法：

```
切到回放场景  →  显示回放源  →  立刻 ReplaySource.Pause（定格在第一帧）
                              ↓  等包装动画放完（本机 2.95 秒；量不出来就等满 3.35 秒）
                         媒体接口 PLAY（同一段素材，从定格那一帧继续）
```

- 插件的暂停是**切换式**的，而 `replay_restart_at_begin` 里
  `pause_timestamp = c->play ? 0 : os_timestamp` —— 刚显示完就暂停，正好停在**片段第一帧**；
  续播走 **obs-websocket 的媒体接口**（`TriggerMediaInputAction` 的 `PLAY`，对应插件
  `replay_play_pause(data, false)`）：只把 `play` 置回 true、把暂停时长补进 `start_timestamp`，
  **同一段素材**从定格那一帧继续，不会跳过片段。
- ⚠️ **续播千万不能用 `ReplaySource.Replay` 热键**（2026-10-06 修）：插件源码里这个热键
  （`replay_hotkey` :1233-1247）打的是 `Load replay pressed`，跟的是 `replay_retrieve()`
  —— 它**重新从滚动缓冲取一段素材**，并且在取素材那一刻按当时的 `start_delay` 重算裁头。
  续播时再取一次，拿到的是"尾巴 = 恢复那一刻"的新素材，内容整体后移。
  现场症状：按 `←` 标的是 21:43:12~14 那一段，播出来却是 21:43:44~46
  （`→` 到按小键盘 Enter 隔了 27 秒，再加 3.35 秒包装转场）。
- 万一这套 obs-websocket 没有 `TriggerMediaInputAction`，退回插件 `ReplaySource.Restart`
  热键（`replay_restart` :676-682：`restart = true; play = true`）—— 仍是**同一段素材**，
  只是从入点重新播一遍，内容不会错。
- 定格那一步也不盲按：先等回放源真的进 `PLAYING`（最长 0.5 秒）再按 Pause，
  否则切换式的 Pause 会把本来停着的源**播起来**。启动时 preflight 会确认一次媒体接口，
  日志里写 `✅ 媒体接口可用：转场放完从定格那一帧续播，不会重新取素材`。
- 播放窗口（引擎掐时间的兜底）也把等待时间算进去了：`replay_until = now + wrap + hold + 5`。
- 转场还没放完就结束了回放（手动切回 / 新回合开打）→ 取消"待恢复"，不会切回直播后又自己播起来。
- 配置：`replay_wrap_seconds`（`null` = 自动读当前转场；填数字 = 强制等这么久；`0` = 回到旧行为）、
  `wrap_pause_max_ms`（默认 250 ms，暂停调用超过它就打警告说片头可能跑掉一点）。
  想连那 0.4 秒的**音效尾巴**一起听完（素材尾巴上有声音），就把 `replay_wrap_seconds`
  填成 `3.35` 手设回去；机器上没装 ffmpeg 时引擎量不出动画结束点，会自动退回"等满文件时长"。
- 当前转场不是 stinger（比如就是淡入淡出）时**完全不等待**，行为和以前一模一样。

### 另外三处会出洋相的地方（2026-10-06 修）

| 症状 | 根因 | 现在的行为 |
|---|---|---|
| 打到第 14 回合，按 Enter 还在播第 11 回合那段 | 旧版"有没有素材"只看历史上有没有成功定格过，永远为真 | 改成必须你自己框过（`←` + `→`）才有素材；没裁过就只提示，不播旧片段 |

### 把成品拷给别人时，对方需要准备什么

**程序本身拷过去就能跑**（`CS2导播助手\` 整个文件夹，含 `_internal\`），不需要 Python、不需要 `pip install`
（`websocket-client` 已打进 exe）。但下面三样**不在这个文件夹里**，得对方机器上本来就有：

1. **OBS Studio 30+**，并且开着 obs-websocket（OBS 28+ 内置，在「工具 → WebSocket 服务器设置」里启用）；
2. **exeldro/obs-replay-source 插件** —— 回放功能完全依赖它。没装的话向导会明确提示去装；
   只用「手机提示器 + 自动切观察位」的话不装也能用；
3. **CS2**，装在**同一台**电脑上（GSI 配置由向导写进游戏的 `game\csgo\cfg\`；换机器要重跑向导）。

然后**跑一次「首次设置向导」**（双击 `先运行我-首次设置.cmd`，或在设置窗口里点「首次设置向导」）：
它会把 GSI 配置装进 CS2、读出 OBS 的 websocket 密码、检查插件、认场景、建回放场景、
放行手机访问的防火墙（这一步会弹 UAC）。

> 拿不准缺什么，就让对方双击 `开始导播.exe` 之后在设置窗口点「内存体检」旁边的命令行跑一句
> `开始导播.exe --selftest`：它会把 `websocket-client`、`tkinter`、键位表、内存公式逐条验一遍，
> 并列出"还差的外部条件"。

> 这个工具**不读游戏内存、不注入游戏、不做任何反作弊会讨厌的事**。
> 数据来自 CS2 官方支持的 **Game State Integration**（只读）；
> 按键注入只发生在**你自己开的 OBS 直播机上**，且只在 CS2 处于前台时才会发生。

## 配置文件

`config.json`（首次设置向导生成，键合并自代码里的 `DEFAULTS`）。常用的几个：

```jsonc
{
  // ---- 连接 ----
  "gsi_port": 23416,                    // CS2 GSI 往这推
  "obs_url": "ws://127.0.0.1:4455",     // obs-websocket
  "web_port": 23417,                    // 手机页面

  // ---- 场景 ----
  "live_scene": "HUD",                  // 直播场景
  "replay_scene": "即时回放",            // 回放场景
  "replay_item": "Replay Source",       // 回放场景里那个回放源

  // ---- 回放 ----
  "record_max_seconds": 10.0,           // 滚动缓冲最长多少秒（会写进插件的 Duration）
  "speed": 0.7,                         // 播放倍速（插件 Speed Percentage / 100）
  "max_hold": 15.0,                     // 回放最多占多少秒（硬上限）

  // ---- 回放功能总开关 + 内存模式（2026-10-07 加）----
  "replay_enabled": false,              // ★ 默认关：四个回放键只提示不动手，插件内存还回去
  "replay_mode": "armed",               // armed = 省内存（按入点键才攒帧）/ buffer = 常驻缓冲
  "free_buffer_after_clip": true,       // armed 下裁完片段是否立刻释放滚动缓冲
  "clear_replay_on_disable": true,      // 关回放 / 切模式时是否连"已取出那段"也清掉
  "memory_report": true,                // 启动时做内存体检
  "memory_autofix": true,               // 体检发现 Maximum replays>1 / internal frames 开着就写回安全值

  // ---- 四个回放键（2026-10-07 起可改；每个动作可绑多个键）----
  "keys": {
    "mark_in": ["left"],                // 标记入点（默认 ←）
    "mark_out": ["right"],              // 标记出点 / 裁片段（默认 →）
    "save": ["numpad6"],                // 保留片段（默认小键盘 6）
    "play": ["numpad_enter"],           // 播放 / 收起回放（默认小键盘 Enter）
  },

  // ---- 手动框选（← 入点 / → 出点）----
  "min_clip_seconds": 0.3,              // ← 到 → 至少隔这么久，防手抖双击
  "manual_lock_seconds": 45.0,          // 人工接管后多久自动交还（0 = 永不）

  // ---- 包装转场（不让 stinger 盖掉回放片头）----
  "replay_wrap_seconds": null,          // null = 自动量当前转场素材里"动画放完"的时刻（本机 3.35s 素材 → 2.95s）；0 = 不等
  "wrap_pause_max_ms": 250,             // 暂停 RPC 超过这么久就打警告

  // ---- 保留片段（默认小键盘 6）----
  "save_replay_key": true,              // 启用"保留片段"键
  "save_dir": "",                       // 留空 = 存到 OBS 录制目录（你的是 E:/Paris2024）
  "save_file_format": "回放_%CCYY-%MM-%DD_%hh.%mm.%ss",

  // ---- 自动切换 ----
  "auto_switch": false,
  "auto_preset": "normal",              // fast / normal / calm
  "auto_win_bonus": true,
  "auto_require_focus": true,           // 前台必须是 cs2.exe 才发键（强烈建议保持 true）
  "auto_focus_exe": "cs2.exe",

  "show_names": false                   // 手机端是否显示玩家名
}
```

手机页面上的开关会**立即生效**，不用重启引擎。

> 📝 `config.json` 现在用 **`utf-8-sig`** 读：记事本"另存为 UTF-8"写出来的带 BOM 的配置，
> 不会再让引擎启动时崩在 `JSONDecodeError` 上了。

## 常见问题

**双击 `开始导播.exe` 为什么弹的是设置窗口，不是黑窗口？**
2026-10-07 起双击 exe 的默认行为就是打开**图形设置窗口**（`5-设置界面.cmd` 同理）。
导播要在窗口里点「**启动引擎**」才开始跑；关掉窗口不影响已经跑起来的引擎。
想直接跑引擎、不要窗口：`开始导播.exe --no-gui`，或者照旧用 `6-director.cmd`。

**为什么按了 `←` / `→` 没反应？**
八成是**回放功能没开** —— `replay_enabled` 默认是 `false`。这时四个回放键只打一行
`（回放功能当前是关的，…不生效）`，**故意不动手**。在设置窗口的勾选框、手机页面顶部的大开关，
或 `--replay on --save-bind` 打开即可。提示器和自动切观察位不受这个开关影响。

**为什么这一用就占 10 G 内存？**
不是泄漏，是插件的未压缩帧滚动缓冲（1080p60 10 秒一份 ≈ 4.98 GB，两份 ≈ 9.95 GB）。
看 [内存：那几 GB 到底是哪来的](#内存那几-gb-到底是哪来的不是内存泄漏) 那一节，
或者双击 `9-memory-check.cmd` / 跑 `--memory-report` 让引擎算给你看。
最省的做法：保持默认的**省内存模式** + `Maximum replays` 保持 1，或者干脆关掉回放功能。

**没有小键盘怎么用（60% / TKL 键盘）？**
打开设置窗口，把「播放 / 收起回放」改成 **`F8`**、「保留片段」改成 **`F9`** 就行
（点「修改」再按一下那个键）。改完 NumLock 提醒也不会再出现。

**⚠️ 电脑会不会被这个工具搞死机？**

**会 —— 当回放插件要的内存超过机器能给的。** 这不是"内存泄漏"，是回放插件的算法：
它把最近 N 秒的**未压缩**帧放内存里，`画布宽×高×4 字节×帧率×秒数`，而且同时留两份。

```
4K60   × 10 秒 × 2 份 = 39.8 GB      ← 32 GB 的机器直接被吃光 → 整机换页 → 死机（含直播卡死）
1080p60 × 10 秒 × 2 份 =  9.95 GB    ← 正常量级；但 16 GB 以下的机器仍然危险
```

所以 **2026-10-08 起内置了三道护栏**（都在设置里能看/能关）：

| 护栏 | 什么时候动手 | 做什么 |
|---|---|---|
| **内存护栏** `memory_guard` | 启动引擎 / 打开回放功能时 | 按**本机内存 + OBS 真实画布**算一遍：装不下就**自动把单段上限降到装得下的值**；高分辨率画布下只能攒不到 4 秒 → **直接拒绝开回放**并告诉你怎么降画布 |
| **资源哨兵** `resource_watch` | 运行期间每 ~2 秒 | 可用内存 <12% 打警告；<6% → **主动把插件的滚动缓冲放掉**（先把我们占的几 GB 还回去），免得整机换页把直播也拖死 |
| **磁盘护栏** | 打开回放功能时 | 系统盘 <2 GB → 拒绝开回放（页面文件都写不进去，必卡）；<8 GB → 警告 |

设置窗口里的内存估算现在读的是 **OBS 配置里的真实画布**，装不下会**红字**告诉你：
`⛔ 内存护栏：本机内存 33.8 GB，这一套设置装不下（峰值要两份 ≈ 39.8 GB）`。

**如果死机时是"整机卡死、直播也卡"**（不是键鼠没反应），按顺序做三件事：

1. **看任务管理器**：死机前"可用内存"是不是贴近 0？系统盘还剩多少？
   —— 内存/磁盘任一贴底，就是资源耗尽，按上面把它降下来。
2. **把「键盘监听方式」改成「轮询」**（设置窗口 ① 回放与按键页）：
   全局键盘钩子有个特性——**回调没返回之前全系统的键盘都在排队**，引擎一旦被拖住就会
   让人觉得整机死了。轮询模式**完全不经过输入管线**，物理上不可能拖住键盘。
   （这条是排查用的对照开关；钩子模式的回调已经改成"只入队、不阻塞"，实测 0.03 ms。）
3. **做对照实验**：开 OBS + CS2 + 推流，但**完全不启动本引擎**，跑一小时看死不死。
   还死 → 与本软件无关（硬件/电源/驱动/网络），用下面的脚本取证。

真要查，在出问题那台机器上用**管理员** PowerShell 跑：

```powershell
powershell -ExecutionPolicy Bypass -File tools\diagnose_freeze.ps1
```

它会把系统日志（Kernel-Power 41 的 BugcheckCode、WHEA、显卡 TDR、磁盘超时、内存耗尽、
应用卡死）、崩溃转储、**OBS 画布与据此算出的插件内存**、可疑输入驱动一起收集成一个 txt
（**只读**，不改任何系统设置）。

> ⚠️ 顺便提醒：**直播进行中按小键盘 6 留档会额外跑一次 x264 实时编码**
> （插件写死 `obs_x264 / CRF23 / veryfast`）。CPU 弱、或者你同时用 CPU 推流时，
> 这一下可能就是"直播开始卡"的起点 —— 想留档尽量放在回合间隙、别和推流抢 CPU。

**根治办法（强烈建议，一次搞定）**：把 OBS 的**基础(画布)分辨率降到 1920x1080** ——
一键工具、不用关 OBS、可回滚：

```bat
python tools\rescale_canvas.py --apply
```

观众看到的本来就是 1080p，所以**画质没有任何变化**，但插件内存直接少 4 倍
（4K 39.8 GB → 1080p 9.95 GB）。

**手机打不开 / 一直转圈**
防火墙拦了。用**管理员权限**双击一次 `8-allow-phone.cmd`。
（向导第 7 步会自动做这件事，只有它失败了才需要手动。）

**自动切换没反应**
看手机页面下面那行状态，它会写 `当前前台：xxx ✗ 不是 CS2，不会切`。
先 Alt+Tab 切回游戏。再确认 CS2 里 `1`~`0` 是观察位切换键（默认就是）。

**回放很短、一闪就没了**
素材长度是按插件里的 `Duration` 算的。检查插件里 Duration 和 `record_max_seconds` 是否一致。

**双击 exe 报 `Could not create temporary directory`**
那是单文件版的问题（每次启动要解压到 `%TEMP%`）。换成文件夹版。

## 常见问题：需要配合 Astra 吗？

**不需要。两者是并列关系，可以同时开着。**

CS2 会加载 `game\csgo\cfg\` 下**所有** `gamestate_integration_*.cfg`，
每份配置各自 POST 到自己的 `uri`，互相不知道对方存在：

| 配置文件 | 推送到 | 谁在用 |
|---|---|---|
| `gamestate_integration_astra_Director.cfg` | `127.0.0.1:23415` | Astra（比分板/数据叠加） |
| `gamestate_integration_pwa.cfg` | `127.0.0.1:55599`（带 token） | 完美世界竞技平台 |
| `gamestate_integration_director.cfg` | `127.0.0.1:23416` | **本工具** |

所以：**不要删也别改 Astra 的配置文件**，本工具的向导也不会碰它。

真正需要留意的只有两点：

1. **热键重叠。** 本工具的键盘钩子是只读的，不会抢 Astra 的键；但反过来，
   本工具的**自动切换**会往游戏里注入数字键 `1`~`0`。
   如果 Astra 恰好也把数字键绑成了自己的功能，它也会收到这些按键。
   建议检查一下 Astra 的热键设置里别用纯数字键。
2. **谁都别同时自动控镜头。** 如果 Astra 那边也开了"自动切观察位"，
   两个工具会互相抢，画面会抖 —— 只留一个。
   （Astra 主要是数据/比分板叠加，一般不管镜头；本工具只读 GSI，因为除了回放和切 POV 之外不干预任何东西 ——
   但**阶段切换/榜单**这类事情仍然交给 Astra 做，本工具不碰。）

**资源占用可以忽略**：两者都只是读 GSI 的 HTTP 推送，开销在千分之一量级。
如果 Astra 也连 obs-websocket，obs-websocket 本身支持多客户端，不冲突。

> 历史提示：早期版本的 Astra 会在冻结时间开头播一个 **7.4 秒**的「Critical Player」卡片。
> 如果你的回放窗口很短，两者会在时间上撞车 —— 那就调低本工具的回放频率，
> 或者在 Astra 里关掉那个卡片。

更多问题见 [使用说明.md](使用说明.md)。
