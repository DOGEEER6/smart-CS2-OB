# smart-CS2-OB · CS2 智能导播副驾

**给单人导播的 CS2 赛事辅助工具：一键回放 + 手机副驾提示器 + 自动切观察位。**

打 CS2 比赛时，导播要同时干三件事：盯着谁在打、把观察位切过去、抓一段刚打完的回放。
一个人干这些基本等于手忙脚乱 —— 镜头切晚了、回放抓早了、精彩镜头全漏了。

这个工具把这三件事各自压缩成一个动作：

| 你原本要做的事 | 现在要做的事 |
|---|---|
| 判断"现在谁在打、镜头该给谁" | **瞄一眼手机**，上面写着大字「按 [ 7 ]」 |
| 交火瞬间腾出手按键、再回放 | 回合结束**按一下 `→`**，最近 10 秒自动成片 |
| 手动切场景、放回放、掐时间切回来 | **按一下小键盘 `Enter`**，播完自动切回直播 |
| 全程手动切 POV | 打开**自动切换**，它替你按数字键 |

## 它解决什么问题

**1. "现在该把镜头给谁"是个实时判断，但导播的手是满的。**
所以判断放在手机上 —— 一张永远只显示"按几号键"的网页，不用装 App，不会打断游戏操作。

**2. 回放和直播抢时间。**
即时回放要么提前开录（占硬盘、还可能错过开头），要么等打完了再想抓（已经晚了）。
这里用 [Exeldro 的 obs-replay-source](https://github.com/exeldro/obs-replay-source) 在内存里滚动缓冲最近 N 秒，
所以**回合结束再按也来得及** —— 精彩的那一秒已经在缓冲里了。

**3. 回放切回来那一下会"卡"。**
常见做法是定时器估算播放时长再切场景，长度算错就会掐掉画面或者黑屏。
这里让**插件自己在播完那一帧切回直播场景**（`next_scene` 属性），引擎只负责收尾。
实测：14.2 秒素材播放全程 17/17 帧画面都在动，没有一帧是静止的。

## 核心特性

- 🎬 **一键定格回放** —— `→` 按一下，最近 10 秒成片，结尾正好卡在回合结束后 1 秒
- ✂️ **入点自动对齐决胜击杀** —— 开头那段"开局静走"自动裁掉，只留击杀前 2 秒（按 `StartDelay`/`trim_front` 真跳，不是快进）
- 📱 **手机副驾提示器** —— SSE 实时推送，浏览器打开就用，不用装 App，口令保护
- 🤖 **自动切观察位** —— 三档灵敏度随时在手机上切，真打起来会绕过门槛直接切
- ⚔️ **对枪胜率预测** —— 按血量/护甲/武器/本场 KD 算这一枪谁能赢，镜头偏向活下来的一方
- 🧱 **交火分层** —— 层级优先于分数，避免"架枪的抢走正在对枪的视角"
- 🛡️ **安全阀** —— 只有 CS2 在前台才发按键；连续切不动会自我停用并打印排查提示
- 🧙 **首次设置向导** —— 自动找 CS2、读 OBS 密码、检查插件、认场景、放行防火墙，8 步零手抄
- 📦 **可以打包成 exe** —— `build_exe.py --clean` 出一个自带 Python 的文件夹版，拷到别人电脑直接跑

## 快速开始

### 方式一：用打好的成品（推荐，不需要装 Python）

```bat
:: 1. 打开 OBS（不用开播）
:: 2. 双击
先运行我-首次设置.cmd
:: 3. UAC 弹窗点「是」
::    看到 "🎉 全部就绪！" 就成了
:: 4. 以后每次开播只双击
开始导播.exe
```

黑窗口会打印一行手机地址，形如：

```
http://192.168.66.221:23417/?k=你的口令     ← 一般是这个
```

手机连同一个 WiFi，打开这个地址（**`?k=` 一起带上**），加进主屏幕书签即可。

### 方式二：从源码跑

```bat
git clone https://github.com/DOGEEER6/smart-CS2-OB.git
cd smart-CS2-OB
pip install websocket-client
python setup_wizard.py       :: 首次设置（--check 只自检、--dry-run 演练）
python replay_director.py    :: 开始导播
```

### 方式三：自己打成 exe

```bat
pip install pyinstaller websocket-client
python build_exe.py --clean
:: 产物：CS2导播助手\   （整个文件夹一起拷走才能用）
```

> 默认打**文件夹版**（onedir）。单文件版（`--mode onefile`）每次启动都要解压到 `%TEMP%`，
> 一旦被组策略 / 杀软 / 沙箱拦就整个起不来，只报一句 `Could not create temporary directory!`，
> 排查代价极高。**建议就用文件夹版。**

### 首次设置向导做了什么

| 步骤 | 干什么 | 安全设计 |
|---|---|---|
| 1 | 找 CS2 安装目录 | 读 Steam 注册表，自动定位游戏库 |
| 2 | 装 GSI 配置 | 只写 `game\csgo\cfg\`，**不碰老版 CS:GO 残留的 `csgo\cfg\`** |
| 3 | 读 obs-websocket 端口和密码 | 直接读 OBS 自己的配置文件，**不用手抄密码** |

| 6 | 写插件参数 | **只写空着的或明显不对的**，你已经调好的值一律保留 |
| 7 | 放行手机访问 | 加一条防火墙入站规则，`remoteip=LocalSubnet` 只放行局域网 |
| 8 | 端到端自检 | 逐项告诉你哪里还没通 |

**对已经配好的系统零改动**，重复跑是安全的。

## 快捷键

全局钩子是**只读**的（`WH_KEYBOARD_LL`，不拦截、不注入、不吞键），CS2 和 OBS 该怎么用还怎么用。

| 按键 | 动作 |
|---|---|
| **`→`** 右方向键 | **定格素材** —— 把"最近 N 秒"存成一段片子 |
| **小键盘 `Enter`** | **播放 / 收起回放** —— 按一下切到回放场景播放，再按一下立刻切回直播 |
| **`1` ~ `0`** | 切换观察位（和 CS2 观察位的 1~0 一一对应） |
| `←` 左方向键 | 开始录制（仅 bracket 模式用，默认的 retrospective 模式不需要） |

> 小键盘 `Enter` 和主键盘 `Enter` 的 `vkCode` 都是 `0x0D`，靠**扩展位**区分，主键盘 Enter 不会误触发。

### 自动切换的三档灵敏度

随时在手机上切，不用重启引擎：

| 档位 | 最小停留 | 领先多少分才切 | 分数门槛 | 适合 |
|---|---|---|---|---|
| **灵敏** | 2.0 s | 6 分 | 30 分 | 交火密集，想跟紧 |
| **标准** | 3.0 s | 10 分 | 38 分 | 默认 |
| **保守** | 4.5 s | 18 分 | 50 分 | 觉得切得太乱 |

还有一个**胜率加成**开关：开着镜头会偏向"预测能活下来的一方"，关掉就是纯看谁在交火。

- 服务端：Python `http.server`，`/` 返回内嵌页面，`/events` 是 SSE 长连接
- 手机端：原生 `EventSource`，无框架、无构建、无依赖
- 鉴权：`/auto?k=TOKEN&on=1`，口令存在 `viewer_token.txt`，**重启不变**（手机书签才有效）
- 网页里**不显示玩家名字**（可开关），因为比赛时看键位比看 ID 快

## 镜头是怎么决定切给谁的

### 第一步：每个 GSI 包给 10 个人打分

GSI 的 `allplayers` 里有**位置**和**朝向**（`forward`），所以能算出"他在瞄谁"：
朝向夹角用 `atan2(forward[0], forward[1])` 求。

| 信号 | 分值 | 含义 |
|---|---|---|
| `taking_damage` | **70** | 这一包血量掉了 —— 最强的信号，他正在挨打 |
| `mutual_aim` | **60** | 他和他面前的敌人互相在瞄 —— 对枪一触即发 |
| `aiming_enemy` | 25 | 他在瞄一个敌人（单向，例如架枪） |
| `enemy_very_close` | 25 | 最近敌人 < 500 单位 |
| `just_killed` | 30 | 3 秒内刚拿到击杀 |
| `last_alive` | 25 | 自己队只剩他一个（残局） |
| `nade_incoming` | 18 | 附近有飞行中的道具 |
| `flashed` | 15 | 被闪了 |
| `has_bomb` | 14 | 拿着 C4 |
| `enemy_close` | 12 | 最近敌人 < 1000 单位 |
| `near_bomb_ct` | 12 | 已下包，他离包很近（拆包位） |
| `low_hp` | 10 | 残血 |
| `sniper` | 8 | 拿狙击 |
| `observed` | 6 | 当前正在看的这个（轻微粘性，防抖） |
| `STICKY_BONUS` | 14 | 上一包的第一名给点加成，防止列表闪烁 |

### 第二步：交火主导权 + **分层**（最关键的修正）

只按分数相加会出大问题：

```
架枪的人       = aiming_enemy 25 + enemy_very_close 25         = 50
包匪+残局+包点 = has_bomb 14 + last_alive 25 + near_bomb_ct 12 = 51
真在打的人     = mutual_aim 60                                 = 60
```

实测复现过：`只按分数排 → 对枪 A 172 / 架枪 D 173`，差 1 分就切错了。
结果就是——**有人正打着，镜头却切到后面拿包的残局哥身上**。

修法是两层：

**① 交火主导权**：只要他正在参与一场即将发生的交火，额外加一大笔分。

```
强交火（互相瞄 / 正在掉血） → +130，并且锁定镜头不许切走
弱交火（单向瞄且敌人很近）  → +70，压得过静态叙事，但不锁镜头
```

**② 层级优先于分数**：排序键是 `(tier, -score)`，不是单纯比分数。

| 层级 | 条件 |
|---|---|
| **tier 0** 真在打 | 正在掉血，或（互相瞄 且 距离 < 1200） |
| **tier 1** 对峙 | 在瞄人 且 距离 < 1600 |
| **tier 2** 其余 | 按叙事价值排（残局、拿包、连杀…） |

于是"架枪的"哪怕叠满静态信号（实测能叠到 243 分），也**永远排在 tier 0 的真交火后面**。
自动切换端也配合：层级跃升时**绕过**分数门槛和领先差值，因为真打起来了必须切。

> ⚠️ GSI **不提供视线遮挡信息**，"在瞄人"只有角度判定 —— 隔墙把准星对着附近敌人也会触发。
> 所以有强弱之分：隔墙瞄人只拿 70 分、不锁镜头，不会把画面焊死。

### 第三步：对枪胜率

镜头应该偏向"能活下来的一方"，所以带一个启发式的胜率模型（**可解释，不是黑盒**）：

```
power = hp × 0.78 + 护甲×6 + 头盔×4 + 武器威力(距离) × 0.52
       − 被闪 22 − 着火了 8 ± 本场 K/D 项 ± 本轮伤害项
prob  = 1 / (1 + exp(−(powerA − powerB) / 22))

加成 = 42 × (prob − 0.5) × 2 × mul     mul = 1.0 互相瞄 / 0.5 单向先手
```

单元测试覆盖：满血 AK vs 残血 AK → 92%；对等 → 50%；AWP 远 63% / 近 36%；
手枪 vs 步枪 26%；被闪 27%；霰弹贴脸 52%；本场 KD 2.5 vs 0.4 → 63%。

> 武器威力按 **(远距离, 近距离)** 两档建表。**只认 `state == "active"` 的那把**——
> GSI 的 `weapons` 字典会残留以前捡过的枪（实测：手里是 `glock`，栏位里躺着 `awp`），
> 按整个武器栏判定会把拿手枪的人算成 AWP 选手，还会连带毁掉胜率预测。

### 第四步：安全阀

- **只有 CS2 在前台才发按键**（`auto_require_focus`，前台进程名必须是 `cs2.exe`）。
  否则合成的数字键会打进 OBS，乱切场景。
- **切完 1.2 秒内回查 GSI 的 `observer_slot`**，看镜头是不是真切过去了。
  **连续失败 3 次就自动关闭自己**，并打印排查步骤（游戏没焦点 / 键位没绑 / 安全软件拦截）。
- 正在回放、镜头被锁（tier 0 近距离互相瞄）时不切。
- 按键用 `SendInput` + **扫描码**（`KEYEVENTF_SCANCODE`）注入，不是 `keybd_event`。
  （验证方式：自己装一个键盘钩子去抓注入的 `7` —— 钩子能抓到，说明通路可用。）

## 一键回放是怎么做到不丢镜头的

```
GSI 看到回合结束 / 你按了 →
        │
        ├─ 插件在内存里滚动缓冲，素材已经在手上了
        ├─ 读 OBS 日志拿到素材真实长度（按字节偏移读新增内容）
        ├─ 算播放时长： hold = 素材秒数 ÷ speed(0.7)
        │
        ├─ 切到回放场景 → 显示回放源 → 触发 ReplaySource.Replay 热键
        │      （参数里写好 next_scene = 直播场景，交给插件自己切回来）
        │
        └─ 收尾：先把场景切回直播，再隐藏回放源
                 （反过来会闪一帧黑屏）
```

踩过的四个坑，都修在代码里了：

1. **定格和播放抢线程** —— 读 OBS 日志要 0.5~1 s，期间用户按了播放键就会读到**上一次的旧素材长度**。
   → 加 `threading.RLock()` 把"选素材 + 读长度 + 算时长"整段锁住。
2. **按文本差异判断 OBS 日志新行是错的** —— `replay added of 12.00 seconds` 每次文本一模一样。
   → 改成按**字节偏移**读新写入的部分。
3. **长度未知时往短了猜** —— 用默认 5 秒估时长，12 秒的素材只播 7 秒。
   → 改成按上限给足，**绝不往短了猜**。
4. **在 obs-websocket 接收线程里发请求 → 死锁** ——
   `on_obs_event` 回调在接收线程里执行，回调里又发 `SetSceneItemEnabled`
   → 响应要由同一个被阻塞的线程来收 → `TimeoutError`。
   → 事件丢进 `queue.Queue()`，由独立的 `_event_loop()` 线程消费。

### 入点是怎么往后挪的

用户实测反馈："前面会截取一些无效片段（不是回合决胜击杀的片段）"。
定格出来的素材结尾固定在回合结束后 1 秒、长度固定 `record_max_seconds`，
所以"击杀发生在素材里第几秒"是可算的：

```
击杀偏移 = 素材长度 - (定格时刻 - 最后一次击杀时刻)
skip     = 击杀偏移 - entry_lead_seconds(默认 2.0)
```

`skip` 写进 Replay Source 的 `start_delay`（**负值**）。插件源码
（`replay-source.c`）里 `replay_retrieve` 对负 `start_delay` 写
`new_replay.trim_front = start_delay * -1`，播放时 `replay_restart_at_begin`
直接 seek 到 `first_frame_timestamp + trim_front` —— 是**真跳**，不是快进；
而且 `|trim_front|` 超过片段总长时插件那个分支不成立，会**原样从头播**，
所以算过头也不会把片子裁没。改这个设置也不会重建滤镜、不会冲掉滚动缓冲。

三道保险：至少留 `entry_min_keep_seconds`；击杀记在不同回合或没记到击杀 → 不裁；
第一次写入时自检一次（写值→读回→比对）并打日志，插件不认这个键就退回"从片头播"。

### 另外三处会出洋相的地方（2026-10-06 修）

| 症状 | 根因 | 现在的行为 |
|---|---|---|
| 打到第 14 回合，按 Enter 还在播第 11 回合那段 | "有没有素材"只看历史上有没有成功定格过，永远为真 | 手里那段不是最近打完那个回合的 → 当场重新定格 |
| 回放中 Astra 把场景切走 → 之后每个回合都不再定格 | 上锁后**只能靠手动按方向键解锁** | 定格不再受锁影响；锁也会在 `manual_lock_seconds`（默认 45 秒）后自动交还 |
| 播完总是硬切回 HUD，即使我是在数据看板上按的播放 | 切回目标写死 `live_scene` | 记下按播放键时所在的场景，播完切回那里；若是**别人**中途切走的，就只收起回放源、不抢画面 |

更多实测结论（插件机制、键盘钩子、GSI 的坑）见 **[docs/技术笔记.md](docs/技术笔记.md)**。

## 环境要求

| 项目 | 要求 |
|---|---|
| 系统 | **Windows**（用到 `WH_KEYBOARD_LL`、`SendInput`、`netsh`，没有跨平台计划） |
| 游戏 | CS2 |
| OBS | OBS Studio 30+，开启 **obs-websocket**（OBS 28+ 已内置） |
| OBS 插件 | [exeldro/obs-replay-source](https://github.com/exeldro/obs-replay-source) —— 回放靠它 |
| Python | 3.9+（用成品 exe 的话**不需要**） |
| 依赖 | 只有 `websocket-client`，其余全标准库 |

> 这个工具**不读游戏内存、不注入游戏、不做任何反作弊会讨厌的事**。
> 数据来自 CS2 官方支持的 **Game State Integration**（只读）；
> 按键注入只发生在**你自己开的 OBS 直播机上**，且只在 CS2 处于前台时才会发生。

## 配置文件

`config.json`（首次设置向导生成，键合并自代码里的 `DEFAULTS`）。常用的几个：

```jsonc
{
  // ---- 连接 ----
  "gsi_port": 23416,                    // CS2 GSI 往这推
  "obs_url": "ws://127.0.0.1:4455",     // obs-websocket
  "web_port": 23417,                    // 手机页面

  // ---- 场景 ----
  "live_scene": "HUD",                  // 直播场景
  "replay_scene": "即时回放",            // 回放场景
  "replay_item": "Replay Source",       // 回放场景里那个回放源

  // ---- 回放 ----
  "record_max_seconds": 10.0,           // 素材最长多少秒（会写进插件的 Duration）
  "speed": 0.7,                         // 播放倍速（插件 Speed Percentage / 100）
  "capture_after_round_end": 1.0,       // 回合结束后多久定格
  "auto_capture_on_round_end": true,    // 回合结束自动帮你定格一次
  "auto_play_after_capture": false,     // 定格后自动播放（默认关，别每回合都放）
  "max_hold": 15.0,                     // 回放最多占多少秒（硬上限）

  // ---- 回放入点对齐（把开头那段"开局静走"裁掉）----
  "entry_align_to_kill": true,          // 按本回合最后一次击杀对齐入点
  "entry_lead_seconds": 2.0,            // 入点留在击杀前几秒（0 = 正好从击杀开始）
  "entry_min_keep_seconds": 2.5,        // 不管怎么对齐，至少留这么多秒可播
  "manual_lock_seconds": 45.0,          // 人工接管后多久自动交还（0 = 永不）

  // ---- 自动切换 ----
  "auto_switch": false,
  "auto_preset": "normal",              // fast / normal / calm
  "auto_win_bonus": true,
  "auto_require_focus": true,           // 前台必须是 cs2.exe 才发键（强烈建议保持 true）
  "auto_focus_exe": "cs2.exe",

  "show_names": false                   // 手机端是否显示玩家名
}
```

手机页面上的开关会**立即生效**，不用重启引擎。

## 常见问题

**手机打不开 / 一直转圈**
防火墙拦了。用**管理员权限**双击一次 `8-allow-phone.cmd`。
（向导第 7 步会自动做这件事，只有它失败了才需要手动。）

**自动切换没反应**
看手机页面下面那行状态，它会写 `当前前台：xxx ✗ 不是 CS2，不会切`。
先 Alt+Tab 切回游戏。再确认 CS2 里 `1`~`0` 是观察位切换键（默认就是）。

**回放很短、一闪就没了**
素材长度是按插件里的 `Duration` 算的。检查插件里 Duration 和 `record_max_seconds` 是否一致。

**双击 exe 报 `Could not create temporary directory`**
那是单文件版的问题（每次启动要解压到 `%TEMP%`）。换成文件夹版。

## 常见问题：需要配合 Astra 吗？

**不需要。两者是并列关系，可以同时开着。**

CS2 会加载 `game\csgo\cfg\` 下**所有** `gamestate_integration_*.cfg`，
每份配置各自 POST 到自己的 `uri`，互相不知道对方存在：

| 配置文件 | 推送到 | 谁在用 |
|---|---|---|
| `gamestate_integration_astra_Director.cfg` | `127.0.0.1:23415` | Astra（比分板/数据叠加） |
| `gamestate_integration_pwa.cfg` | `127.0.0.1:55599`（带 token） | 完美世界竞技平台 |
| `gamestate_integration_director.cfg` | `127.0.0.1:23416` | **本工具** |

所以：**不要删也别改 Astra 的配置文件**，本工具的向导也不会碰它。

真正需要留意的只有两点：

1. **热键重叠。** 本工具的键盘钩子是只读的，不会抢 Astra 的键；但反过来，
   本工具的**自动切换**会往游戏里注入数字键 `1`~`0`。
   如果 Astra 恰好也把数字键绑成了自己的功能，它也会收到这些按键。
   建议检查一下 Astra 的热键设置里别用纯数字键。
2. **谁都别同时自动控镜头。** 如果 Astra 那边也开了"自动切观察位"，
   两个工具会互相抢，画面会抖 —— 只留一个。
   （Astra 主要是数据/比分板叠加，一般不管镜头；本工具只读 GSI，因为除了回放和切 POV 之外不干预任何东西 ——
   但**阶段切换/榜单**这类事情仍然交给 Astra 做，本工具不碰。）

**资源占用可以忽略**：两者都只是读 GSI 的 HTTP 推送，开销在千分之一量级。
如果 Astra 也连 obs-websocket，obs-websocket 本身支持多客户端，不冲突。

> 历史提示：早期版本的 Astra 会在冻结时间开头播一个 **7.4 秒**的「Critical Player」卡片。
> 如果你的回放窗口很短，两者会在时间上撞车 —— 那就调低本工具的回放频率，
> 或者在 Astra 里关掉那个卡片。

更多问题见 [使用说明.md](使用说明.md)。
